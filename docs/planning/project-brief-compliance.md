## Perbaikan yang masih perlu dikerjakan pada kode

1. Simpan alasan penolakan SO agar jejak keputusan review lebih lengkap. Aktor pada movement Receipt/Issue baru sudah tercatat; transaksi historis tetap tanpa aktor.
2. Tambah unit coverage authorization dan low-stock serta wire service/repository melalui composition root yang eksplisit.
3. Tinjau ulang kebutuhan opsional alasan penolakan SO, unit authorization/low-stock, dan composition root sebelum rilis. Angka dashboard, permission, ekspor, dan respons saat database gagal sudah diuji.
4. Latih demo alur tiga role dan siapkan screenshot sebagai bukti cadangan. Bukti runtime, screenshot 360px/desktop, API 200/401/404, test, PHPStan, dan CSV dua rentang sudah dicatat.
